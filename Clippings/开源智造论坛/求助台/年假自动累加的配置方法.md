# 年假自动累加的配置方法

> [!info] 来源
> 开源智造论坛 · 求助台 | 作者:肖相扶 | 2022-12-15
> <http://www.thinkltd.cn/forum/1/932>

1.  【20220715】参考此功能增强模块，[年假python代码自动计算hr_holidays_annual](http://www.thinkltd.cn/forum/2/question/pythonhr-holidays-annual-3571)

2.  Odoo15中，休假管理模块(hr_holidays)有自动计算年休假的功能，设置菜单：Time off --> Configuration --> Accrual Plans。

3.  例如，客户FEV的年假规则是：新进员工年休假10天，第一年的年假天数，按实际入职日期，除以全年天数计算，按比例折算年假天数。之后，每工作两年增加1天年假，年假封顶15天，每年年末，当年未休万的年假清零。

4.  配置要点：1）为每个员工配置一个年假分配计划，开始日期是该员工的入职日期；2）第一个年假计算Level上，年假数和上限都是10天；3）第二个年假计算Level，开始日期是24个月后，年假数和上限是11天；4）第三个年假计算Level开始日期是48个月后，如此重复，每24个月一个Level，共配置6个Level 。

5.  系统通过计划任务 Accrual Time Off: Updates the number of time off ，查找待计算的假期分配，计算年假。假期分配上有隐藏字段 lastcall、nextcall 。lastcall记录上次的年假计算时间，nextcall 是下次计算的时间。

6.  注意：测试发现此功能存在Bug（Bug：假期分配的第一期年假计算被跳过，而是从第二期开始计算年假），要按下述修改代码。文件 OSCGODOO15\source\addons\hr_holidays\models\hr_leave_allocation.py，方法 def _process_accrual_plans(self)，有两处修正。1）原412行（前后）代码行 allocation.nextcall = first_level._get_next_date(allocation.lastcall)  替换为  allocation.nextcall = allocation.lastcall  ；  2）443行前后，如下截图所示，代码行中的 allocation.nextcall 换成 nextcall

- Start after：假期分配（Allocations）上的起始日期后的多少时间开始计算年假

- Rate、Frequency：每个期间（年、月等），增加多少天年假，从几月几号开始加

- Based on worked time：（一般适用于非全职员工）该员工的工作日历表上的工作天数，占总天数的比例，乘以Rate数量，作为年假数。

- Limit to：截至该年假计算期间，累计的剩余年假的上限。例如，以本例设置为例，如果该员工上一年的年假10天，一天未休，则第二年系统计算该员工年假时候，他还是10天（已达10天的上限）。如果上一年该员工休了年假8天（有该年假类型的请假单），则第二年系统计算该员工的年假是18天（去掉已休的8天，实际剩余年假还是上限值10天）。

- At the end of the calendar year, unused accruals will be： Transferred to the next year , Lost两个选项。注意，此设置项的含义不是说上一年未休完的年假是否累加到下一年。其含义是，过去时间段的年假要计算还是废弃。例如，为每个员工配置一个年假累加计划，开始日期是该员工的入职日期，今年1月1号开始上线Odoo HR系统，则入职到今年1月1日的年假是废弃，还是计算进来？如果年假计划的开始日期直接配置成今年的1月1日，则此设置项实际没有意义。
