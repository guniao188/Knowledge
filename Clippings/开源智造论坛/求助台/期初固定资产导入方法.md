# 期初固定资产导入方法

> [!info] 来源
> 开源智造论坛 · 求助台 | 作者:葛忠彪 | 2025-02-27
> <http://www.thinkltd.cn/forum/1/4041>

附件是客户真实数据，请注意保密

需要导入的内容有

name：建议用资产名称+资产型号   如果客户多台设备以前没分开资产卡片的，odoo里不打算分开的（其实建议要分开，不然后续单台处置不好处理），那么把数量也拼到名称里去

prorata_date：开始折旧日期，即第一张折旧计提凭证的日期

method_number：折旧期数

method_period：折旧模式，按月折旧填写1，按年折旧填写12

original_value：原值，通常是采购回来的未税金额

already_depreciated_amount_import：截止到期初开账时，已折旧金额

salvage_value：残值，即不可贬值金额，通常是10%或者5%

account_asset_id：资产科目

account_depreciation_id：累计折旧科目

account_depreciation_expense_id：费用科目

上述是基本要导入的内容

导入后，使用odoo自带的计算折旧方法（form上的按钮或者服务器动作），系统跑出折旧计提凭证，同时结合已折旧金额，会自动忽略掉已折旧金额对应的历史凭证

不过会出现一个小情况，例如

原值 230088.5  残值 23008.85  120个月  月折旧 1725.6634XXXX

odoo会按照准确的月折旧金额四舍五入，例如  1725.6634  那么会是每2个月计提  1725.66 然后下一个月计提 1725.67 的处理方式，确保所有折旧计提完成后，累计折旧金额=原值-残值

而金蝶用友可能不是这么处理的，而是直接四舍五入每月折旧 1725.66

这样的话，odoo导入上述excel，以25年1月1日开账，系统会跑出一张24年12月31日 -0.07的折旧计提凭证

我的处理方法是，把这部分差异，直接计入残值里（客户财务也同意这个做法），服务器动作如下：

```python
for record in records:
move = [record.depreciation_move_ids.filtered(lambda](https://record.depreciation_move_ids.filtered(lambda) m: [m.date.year](https://m.date.year) == 2024)

raise UserError(record.name)

```

salvage_value = record.salvage_value + abs(move.line_ids[0].balance)
record.write({'salvage_value':salvage_value})
move.unlink()

如果25年开账，那么差异凭证只能有一张，所以先检查每个资产24年的凭证是否多余1张

同时差异金额只应该是小数尾差产生的，所以检查是否超过0.3元（因为客户有已经折旧3年的资产，所以这个差异我放稍微大一点）

如果都没问题，就把差异加在残值里，然后删除24年的计提凭证
