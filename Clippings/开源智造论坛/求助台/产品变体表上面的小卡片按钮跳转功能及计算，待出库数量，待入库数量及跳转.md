产品变体表上面的小卡片按钮跳转功能及计算

客户需求：想通过表头的地方，一目了然的看到在手数量、预测数量、尚未出货或领用的数量、尚未收货或生产入库的数量清单，并且象其他小卡片一样，可以跳转到详情的列表清单上查看具体是哪些单据正在等待，不用用户另外再过滤查找。

实现方法及步骤说明：(有补上条件partially_available部分可用也要考虑进去，故代码上有补上这个状态）

第一步，先创建stock move的二个窗口动作，并设好菜单过滤条件，并绑定好相应的外部ID:

![[1-872-d2017fdb.png]]

菜单过滤条件：['&','&','&',('product_id.type','=','product'),('state','in',('assigned','confirmed','waiting','partially_available')),('location_id.usage','=','internal'),('location_dest_id.usage','!=','internal')]
过滤出：可库存商品并且stock move的状态是待办，源位置是内部位置，目的位置是非内部位置即虚拟位置的记录；

外部ID的设置：绑定好该窗口动作的数据库ID

![[1-872-aacc48db.png]]

![[1-872-8fd436f1.png]]

入向的菜单过滤条件：['&','&','&',('product_id.type','=','product'),('state','in',('assigned','confirmed','waiting','partially_available')),('location_id.usage','!=','internal'),('location_dest_id.usage','=','internal')]
是产品并且状态是待办并且来源位置非内部并且目的位置是内部，表示入库并且是未完成的单据

![[1-872-65306d0b.png]]

第二步，创建二个服务器动作，因二个小卡片是基于产品变体来看的，故需要服务器动作设置在产品表，并加好过滤条件，与设置的窗口动作条件类似

出向代码：domain中是点按钮的过滤条件，action=env括号中是调用的第一步设置的窗口动作的外部ID值

domain = [ ('product_id', '=', record.id),('state','in',('assigned','confirmed','waiting','partially_available')), ('location_id.usage', '=', 'internal'), ('location_dest_id.usage', '!=', 'internal') ]
action = env.ref('stock.outgoing_qty_search').read()[0]
action['domain'] = domain

![[1-872-82ce35c1.png]]

入向代码服务器动作：

domain = [ ('product_id', '=', record.id),('state','in',('assigned','confirmed','waiting','partially_available')), ('location_id.usage', '!=', 'internal'), ('location_dest_id.usage', '=', 'internal') ]
action = env.ref('stock.incoming_qty_search').read()[0]
action['domain'] = domain

![[1-872-f7c4f0c2.png]]

第三步，将这二个服务器动作的数据库ID记下来，并写入到产品变体的form继承视图中：
