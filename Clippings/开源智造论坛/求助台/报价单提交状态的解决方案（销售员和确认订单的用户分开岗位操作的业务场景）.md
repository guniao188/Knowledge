# 报价单提交状态的解决方案（销售员和确认订单的用户分开岗位操作的业务场景）

> [!info] 来源
> 开源智造论坛 · 求助台 | 作者:符赛红 | 2022-12-15
> <http://www.thinkltd.cn/forum/1/783>

适应的业务场景说明：以下的解决方案，适应于销售员和确认订单的用户是分开不同角色用户操作的情况下，而且用户需要有个区分哪些报价单是要确定下来往后走流程的情况。

***这个方案也适应于其他数据表菜单下的简版的审批流的处理，举一反三哦!***

在销售端，crm到订单的这个过程参考：

销售员：crm跟进——》报价单——》报价单发货——》客户反馈需要订货——》****销售员提交报价单****（现在要加的是这个节点，是为了能有个标记，在二个用户间交接时，能直接通过系统查看到哪些订单应该要进行审批【确认订单】，否则，就会导致二个岗位间交接时，还得线下口头或书面传递单号，负责审批的人才知道要去确认订单）

![[1-783-f6c4a187.png]]

销售主管/组长/助理：审核【确认订单】——》变成订单及生成仓库的发货单

****这是关于销售员和助理岗位分离时，会涉及到报价单什么情况下要去确认订单的解决方案参考。避免开发去改系统原生的state状态逻辑。****

配置要点：（主要解决的问题是，二个岗位间交接时，下一个人得明确知道哪些单据是需要去【确认订单】的。）

增加了独立的菜单：Wait For Confirm    菜单的domain条件：过滤出是已提交并且状态是在报价单或报价单发送状态的单据[('x_is_confirm','=',True),('state', 'in', ('draft', 'sent'))]

![[1-783-c14a93af.png]]

增加字段及左上角的按钮：

![[1-783-93bc8cf5.png]]

form里面的继承视图添加：这个提交按钮是给销售员点的，故只在报价单或报价单发送状态下出现即可，而且这个字段不能直接界面上编辑，为只读：

![[1-783-86a28bdd.png]]

左上角的按钮，是通过服务器动作实现的：

```python
for line in records:
  if line.state == 'draft' or line.state == 'sent':
    line.write({'x_is_confirm':True})
```

![[1-783-60130218.png]]

再进行配置自动动作，当报价单或订单取消时，需要重新走提交流程，故变成取消状态时，要把这个布尔型字段变成false

![[1-783-9ef451bb.png]]

```python
for line in records:
  if line.state == 'cancel':
    line.write({'x_is_confirm':False})
```

服务器动作有加入到菜单中，故用户也能批量提交。

![[1-783-925fb2d9.png]]
