# 系统跑订货规则的时候，每天跑出的补货单据可以不合并吗？

> [!info] 来源
> 开源智造论坛 · 求助台 | 作者:肖相扶 | 2022-12-15
> <http://www.thinkltd.cn/forum/1/578>

【问题背景】

1.  系统的订货规则，每天运行安全库存调度，根据补货规则，跑出补货单据（采购单、调拨单）。实际运行中，有个问题，就是昨天跑出的PO单，正在和供应商洽谈采购，今天跑出的PO需求又合并进来了，导致本来已经确认过的PO Item又变了。Item多了，不知道哪些是确认过的，哪些是新加进来的。

2.  希望系统每天MRP跑出的PO单不要自动合并，一天一单（同一天同一个供应商的合并）。

【解决方案】

1.  经调查，再订货规则上，有补货组（group_id）字段。系统本来的逻辑是（路线规则stock.rule的传播补货组字段，注意选择传播，默认是不传播），补货组相同的补货单合并，不同的不合并。

2.  每天跑MRP之前，给所有再订货规则设定以当天日期为名的补货组，则跑出的PO等补货单据不会合并到昨天的单据上。可以在运行计划任务的python代码上，追加逻辑：1) 创建当天日期为名的补货组; 2) 补货组写入所有再订货规则。

## 补充/答案 1

【实现截图】

追加逻辑后的计划任务代码：

dd = datetime.datetime.now()
group_name="OP%s%02d%02d" % (dd.year,dd.month,dd.day)
group_id = env['procurement.group'].search([('name','=',group_name)])
```python
if not group_id:
    group_id = env['procurement.group'].create({'name': group_name})
else:
    group_id = group_id[0]
env['stock.warehouse.orderpoint'].search([(1,'=',1)]).write({'group_id':group_id.id})
```

model.run_scheduler(True)
