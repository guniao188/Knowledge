# 仓库出入库单在临出入库验证前需要更改仓别或位置，即作业类型，该如何操作？

> [!info] 来源
> 开源智造论坛 · 求助台 | 作者:符赛红 | 2022-12-15
> <http://www.thinkltd.cn/forum/1/572>

在实际业务中，会存在一种情况是在下订单时，比如决定是要进A仓，或者说在下订单确认时，尚不知道入哪个仓，就选择了一个默认的仓，待实际仓库到货时，才知道进了哪个仓，或者哪个仓有货，需要临时修改从另一个仓位发货，如果odoo以前的版本，需要取消SO或PO，重新在订单上选择好仓别或者是仓别或位置对应的入库作业类型，方可修改实际入或出的位置，如果订单还涉及审批，或者涉及某个订单已有部分入库或出库的情况下，订单是不允许取消再重置的，这就导致操作上很麻烦。

为解决这一问题，可以从技术上解决。

答: 解决方案，主要围绕着picking回到草稿状态下，可以来修改作业类型及改变位置，重新保留的方向调整解决,但如果SO订单是make to order生成的，或是picking单上是等待其他作业，重置为草稿后，需要采购入库单与销售出库单的仓位是一样的，即相互承接对应的，否则会报错，无法make as todo。

编写服务器动作（注意缩进位置）

for record in records:
 if record.state not in ['done', 'cancel']:
```python
    record.do_unreserve()
    record.write({'state': 'draft'})
    if record.move_ids_without_package:
     for move in record.move_ids_without_package:
      move.write({'state': 'draft'})
    if record.move_line_ids_without_package:
     for move_line in record.move_line_ids_without_package:
      move_line.write({'state': 'cancel'})
```

说明：改进后，可以不用经过【取消保留】，可以直接点【状态改草稿】。

然后在picking单的视图中加入这个左上角的按钮

因这个按钮只是特殊情况，故有设这个按钮的权限为：仓库管理员才能操作

特别注意：

如果是入库单的修改，可以直接照上面操作即可。

如果是出库单的修改，需要特别注意，产品是否是make to order生成的出库单或是有多步要等待其他作业的单据而产生的，如果是，需要从相互关联的上游单据更改做起，前后单据需要一致，入库单的入库位置需要与出库单出库位置一致！

否则会出现这个报错，导致无法草稿状态之后下一步操作make as todo

![[1-572-3fb51190.png]]

当解决了上游的入库单入库位置也跟着改成一致后，就可以正常往后操作了。

说明：这里有个改后的小点注意，只是改了作业类型，默认的位置变了，但因单据是前面订单确认时生成的，故当时生成单据的单号，不会再发生变更。

除非另外加模块，用程序去解决更改作业类型时，同时变更单据的编码为该作业类型的编码单号。

如果有这个V13的模块，那就更完美了。改仓别就能直接在仓库端更改，而不用取消订单重走流程了。
