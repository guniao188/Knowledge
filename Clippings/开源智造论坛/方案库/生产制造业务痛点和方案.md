# 生产制造业务痛点和方案

> [!info] 来源
> 开源智造论坛 · 方案库 | 作者:肖相扶 | 2025-04-16
> <http://www.thinkltd.cn/forum/3/3594>

【业务痛点】

1.  生产计划
2.  1.  基于各规格产品的需求数量、需求日期，以及车间产能，制定未来一段时间的生产计划，包括生产什么、生产多少、什么时候生产。落实到系统的操作是，基于什么创建生产订单MO。
```python
    2.  基于订单生产（MTO）：产成品的补货路线设置为MTO，则有销售订单时候， 系统自动为订单上的产品创建对应的制造订单MO。按客户要求定制的产品，通常用此方法。
    3.  主生产计划（MPS）：计划部门基于需求预测（市场预测），滚动计划各规格产品的需求数量（MPS），系统基于此数量创建生产订单MO。市场需求较为平稳的产品，或者内部的一些通用部件，可以用此方法。参考 [Odoo16生产计划/生产管理详解(MPS功能)](http://www.thinkltd.cn/forum/1/odoo16-mps-3652) 、 [Odoo13企业版主生产计划mrp_mps](http://www.thinkltd.cn/forum/2/odoo13mrp-mps-3360)
    4.  基于缺货数量生产：系统列示各产品的需求数量、库存数量、缺货数量，手动填写补货数量，系统基于补货数量创建生产订单MO。需求不稳定（难以预测），不同订单可以合并生产的时候，可以用此方法。补货池功能参考  [Odoo14自动产生补货规则（订货规则Order Point）原理](http://www.thinkltd.cn/forum/1/odoo14-order-point-766)
```

3.  物料需求计划
4.  1.  基于生产计划，计算各原料（物料）需求数量，减去库存数量，得到缺口数量，制定采购计划
```python
    2.  先生产计划，再采购计划。Odoo默认方式是，制定生产计划（创建和确认MO），系统再展开MRP，计算物料需求和缺口数量。物料采购入库时候，各MO自动锁定物料。此方法的好处是，计划性强，自动化程度高，库存积压小。缺点是，如果供应链不稳定，供应周期长，生产计划经常调整，此方法会导致经常改单（修改MO单）。
    3.  先采购计划，再生产计划。先计算物料需求，下采购计划。基于物料齐套情况，再制定生产计划（创建生产订单MO）。供应链不稳定，产品类同性高，生产数量大，插单多的情况，适用此方法。参考  [物料需求计划模块purchase_mps](http://www.thinkltd.cn/forum/2/purchase-mps-3529)
    4.  替代料：参考  [简易替代料功能模块mrp_substitute_products](http://www.thinkltd.cn/forum/2/mrp-substitute-products-3554) 以及  [二开生产替代料功能模块mrp_substitions、purchase_split_substitions](http://www.thinkltd.cn/forum/2/mrp-substitionspurchase-split-substitions-3396)
```

5.  生产制令
6.  1.  基于生产订单MO，打印生产制令，下发车间生产的处理过程。参考  [Odoo16车间调度功能讲解](http://www.thinkltd.cn/forum/1/odoo16-3653)
```python
    2.  一单一单生产的情况：按生产要求，设定制令单格式，基于MO打印生产制令单
    3.  合并生产的情况：多个MO单一起生产，典型情况如，激光裁板，多个小零件一起裁出。又如服装生产行业，同一款型，不同颜色尺寸的服装，合并下单给车间生产。参考  [生产单（MO、PO）批量报工结单及工作中心分时段成本设置mrp_production_batch、mrp_workorder_cost](http://www.thinkltd.cn/forum/2/mopo-mrp-production-batchmrp-workorder-cost-3482)
    4.  分拆生产的情况：有时一个大单，拆分到不同车间、不同时段生产。还有些情况，化工类生产，计划生产A（创建了一个生产A的MO单），实际生产过程中，可能产出了若干A，若干B。一种处理办法是，将A的MO单分拆成A的MO单和B的MO单。参考  [生产订单MO分拆模块mrp_production_split](http://www.thinkltd.cn/forum/2/momrp-production-split-3480)
```
