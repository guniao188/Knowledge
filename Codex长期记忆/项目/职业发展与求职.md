# 职业发展与求职

## 职业定位

- 主定位：Odoo 实施顾问 / ERP 项目经理。
- 核心能力链：需求调研 → 业务蓝图 → Odoo 配置与定制协调 → UAT → 用户培训 → 上线切换 → 运维支持。
- 差异化能力：计算机专业背景，Python/SQL/轻量二开，以及面向实施场景的 AI 工作流设计与内部推广。

## 简历成果表达

- AI 经验应写成需求纪要、实施方案、操作手册、Odoo 问题诊断等具体场景；以“典型任务耗时降低约 30%”描述，避免未经充分证据支持的公司整体效率结论。
- 数量口径采用漏斗关系：参与 70+ 项目及专项交付、主责 50+、完成 60+ 上线或阶段性交付；投递和面试前仍需确认统计定义。
- 工作成果可突出并行推进 5+ 项目、2025 年可计费交付与工时表现；具体指标名称和统计依据在对外使用前需要复核。
- 精选项目按“范围—职责—难点—结果”书写，避免多个项目长期统一写“至今”。
- 面试项目回答固定用“角色—职责—难点—行动—结果”，难点至少一半用于说明解决过程；把中绿案例表述为供应链假设经试运行修正、补货与交期政策联动，不指责具体部门。
- 核心优势可归纳为“业务理解 + 技术落地 + 知识沉淀 + 多项目管理”；“相关场景效率提升约 30%”比“公司整体提升 30%”更稳健。

## 当前求职衔接

- 工作假设/待确认：正在推进新公司 Offer，同时原劳动合同尚未正式解除，并存在一笔绩效结算争议。
- 已形成的风险控制思路：在旧劳动关系解除前保持正常履职并留存合同、绩效和沟通证据；不把“个人原因辞职”“全部款项已结清”等与事实不符的表述写入解除协议；绩效、工资、补偿及付款日期分别写清。
- 解除协议与离职证明用途不同；协议中应约定解除日期、款项、离职证明及社保/档案转移。向新公司只需如实说明正式解除日期、到岗安排和可能有效的竞业限制，无需主动披露绩效金额。
- 风险：是否可按欠付劳动报酬主张解除和经济补偿，取决于绩效制度、考核结果、应付日、所在地裁判口径及证据；金额较大或拟发正式解除通知前应让当地劳动专业人士复核。
- 已形成邮件版“辞职通知及薪资绩效结算确认”草稿：最后工作日与公司另行书面确认；可设置邮件送达满 30 日作为兜底日期，避免无限期悬而未决。
- 草稿要求公司书面确认已到期待结绩效、当月实际绩效、其他应付款、离职证明及社保/公积金手续；提交交接不代表放弃未付报酬请求权。
