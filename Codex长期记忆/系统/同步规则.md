# 同步规则

## 每日 17:00 流程

1. 读取 [[同步状态]] 中的上次成功时间。
2. 列出 Codex 最近任务，只处理此后有更新的任务；忽略自动化自身产生的重复内容。
3. 再从最近任务中选取最多 5 个未出现在 [[已处理任务]] 的旧任务，做渐进式历史回填；新任务优先。
4. 读取相关任务的新增沟通，按项目归类。
5. 写入当日 `日报/YYYY-MM-DD.md`。
6. 仅在状态、决策、风险、下一步或稳定偏好变化时更新项目页、[[../03-决策日志]]、[[../01-工作画像与协作偏好]]。
7. 成功后更新同步状态和已处理任务；若部分任务不可读，记录缺口但不覆盖旧结论。

## 写入准则

- 写结论与依据，不复制整段对话和大段代码。
- 保留项目名、日期、来源任务标题/ID、交付物绝对路径。
- 同一事实更新原条目；不要每天追加重复内容。
- 状态冲突时保留最新有证据结论，并记录“被什么更新”。
- 推测必须标注 `工作假设` 或 `待确认`。

## 隐私与安全

- 不记录密码、API Key、Cookie、访问令牌、身份证号、银行卡等秘密或高敏信息。
- 客户业务只记录完成任务必需的上下文；原始附件留在原位置。
- 自动化只写 `/Users/yaodaidi/知识库/Codex长期记忆`，不改动既有 OSCG 原文和 Obsidian 配置。
- 正式系统部署、发消息、改数据库等外部动作不属于本自动化范围。

## 历史回填边界

- Codex 任务列表只暴露当前可访问的最近任务；不能把“未返回”解释为“不存在”。
- 每次最多回填 5 个旧任务，以稳定质量和运行时间；已处理 ID 写入 [[已处理任务]]，避免重复全文读取。
- 旧任务若只包含一次性排错且没有稳定复用价值，只在已处理清单登记，不扩写项目页。
