# 决策日志

## 2026-08-04：采用本地 Obsidian 作为 Codex 跨项目长期记忆

- 状态：已确认
- 决定：使用当前 Obsidian 已打开的 `/Users/yaodaidi/知识库`，新增 `Codex长期记忆`，不使用空的 iCloud 同名库。
- 原因：现有库已有 OSCG 客户档案、通用知识和操作手册；直接链接可避免内容分叉。
- 机制：每天 17:00 汇总当天 Codex 项目沟通，更新日报、项目状态、决策和偏好。
- 读取：全局 `~/.codex/AGENTS.md` 要求新任务在涉及历史上下文时先读记忆入口，再按需读取相关页。
- 边界：不复制整段聊天；不记录密码、令牌、密钥和无必要的客户敏感数据；不把推测写成事实。

## 跨项目研发与交付决策

### Odoo 多版本隔离

- 状态：长期原则
- 决定：17/18/19 的实现与兼容说明分开维护；修改前必须确认版本。
- 原因：字段、视图语法、OWL 与业务行为存在版本差异。

### 数据修复采用可回滚流程

- 状态：长期原则
- 决定：数据修复先统计与预览，导出修改前数据，确认后执行并输出结果。
- 原因：临时服务器动作容易误改，且历史数据影响范围常不明确。

### 正式库部署保留人工确认

- 状态：长期原则
- 决定：自动检查、备份、同步、测试可自动化；正式库升级和不可逆修改需人工确认。
- 原因：生产影响与回滚成本较高。

### 客户交付内容区分事实层级

- 状态：长期原则
- 决定：文档明确区分“已演示/已实现”“实施建议”“待客户确认”。
- 原因：避免把规划功能误写成已上线承诺。

### Odoo Git 仓库只保存源码

- 状态：已确认
- 决定：Odoo 18/19 仓库只提交代码，排除数据库、转储、虚拟环境、运行数据、本地配置和凭据。
- 提交方式：按具体模块暂存和提交；Odoo 19 存在大量 Enterprise 嵌套仓库差异时禁止直接使用 `git add -A`。
- 原因：避免上传客户数据、秘密、大文件及非本次修改。
- 来源：`创建并推送 Odoo 分支`，thread `019f70fa-c257-7cd1-b234-a6d0e60f4436`。
